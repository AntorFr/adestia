# Inventaire — serveur

Statut : complet

Les tests hors écran sont des tests que la suite attestée joue. Un fichier est nouveau : `packages/server/test/catalogues-retrait-hors-ecran.test.ts` (retrait d'un catalogue par sa route : l'autre catalogue reste, le retrait survit au redémarrage, les copies importées s'en vont avec lui et pas les autres, la liste des instructions ne les montre plus, la même adresse déclarée de nouveau repart sans import). Les autres sont des tests déjà présents (`catalogues-ensemble`, `bench-launcher`, `pages`) : les effets de catalogue ont leur porte dans les routes du serveur.

`À l'écran` dit `gardé` partout : le codeur ne modifie ni ne retire un test existant. L'allègement ou le retrait des lignes `effet` et `scindé` revient au testeur, une fois le test hors écran rejoué.

Trois constats sur la grappe :

- Les tests de balayage (`bench-ensemble`, `bench-besoin` B-3, `bench-sweep` « real browser ») vérifient des captures : taille, thème, différence entre images. C'est de l'affichage, entier.
- Beaucoup de tests de ces fichiers ne pilotent aucun navigateur : le lanceur (`bench-besoin` B-2, `bench-launcher`), les refus d'arguments du balayage, les routes et la délégation de `qualite-serveur-ensemble`. Ils sont déjà hors écran ; ils n'ont rien à reporter et gardent leur ligne en `sans-porte`, avec cette raison (la classe n'a pas de case « déjà hors écran »). `bench-launcher` ne nomme pas de navigateur du tout.
- Le test « fake engine, ping » de `bench-ensemble` est le seul à mêler une règle (le moteur factice répond « pong ») à un affichage (le mot dans le fil) : il est `scindé`.
